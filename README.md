# Граф зависимостей npm

**Практическая работа № 2 · Вариант 26 · Конфигурационное управление**

Консольное приложение на Python для анализа прямых и транзитивных зависимостей
npm-пакетов. Программа строит ориентированный граф рекурсивным поиском в глубину
(DFS), обнаруживает циклы и сохраняет результат в форматах D2 и SVG.

Сведения о зависимостях извлекаются собственным кодом из JSON API npm-реестра.
Для этого используются только стандартные модули Python `urllib` и `json`.

## Возможности

- Настройка через JSON-файл с проверкой всех обязательных параметров.
- Получение прямых и транзитивных зависимостей из npm-реестра.
- Выбор версий по точному номеру, тегу или поддерживаемому диапазону SemVer.
- Рекурсивный DFS с обработкой общих зависимостей и циклов.
- Исключение пакетов по подстроке имени.
- Тестовый режим с локальными графами без обращения к сети.
- Вычисление порядка готовности зависимостей для графов без циклов.
- Экспорт D2 и SVG, вывод ASCII-дерева в терминале.

## Требования

| Компонент | Для чего нужен |
| --- | --- |
| Python 3.10 или новее | Запуск приложения и тестов |
| [D2](https://d2lang.com/tour/install) | Создание SVG на этапе 5 |
| Доступ к интернету | Работа с настоящим npm-реестром |
| Node.js и npm | Только отдельный скрипт сравнения с npm |

Сборка и установка Python-зависимостей для приложения не требуются.
На этапах 1–4 D2 не нужен. Локальные тестовые графы работают без интернета.

Для экспорта SVG установите D2 и проверьте его доступность:

```console
d2 --version
```

Программа также ищет D2 в `tools/d2/d2.exe` на Windows или `tools/d2/d2`
на Linux/macOS. Путь можно задать через переменную окружения `D2_BINARY`.
Исполняемый файл D2 не включен в Git-репозиторий.

## Быстрый старт

Откройте терминал в каталоге этой работы — рядом с `run.bat` и `pyproject.toml`.
Если работа находится внутри общей папки с практиками, сначала перейдите в нее:

```powershell
cd "2 практика"
```

**1. Проверьте запуск без сети и D2:**

```console
python src/main.py examples/configs/diamond.json --stage 3
```

**2. После установки D2 создайте изображение:**

```console
python src/main.py examples/configs/diamond.json
```

**3. Откройте `output/diamond.svg` в браузере.** Рядом будет сохранен исходник
`output/diamond.d2`. В терминале появится дерево:

```text
A
|-- B
|   `-- D
`-- C
    `-- D [shared]
```

Стрелка `A -> B` означает, что A зависит от B. Метка `[shared]` обозначает
повторно встреченную общую зависимость, а `[cycle]` — возврат по циклу.

Альтернативный запуск на Windows:

```powershell
.\run.bat examples/configs/diamond.json
```

На Linux/macOS:

```sh
sh run.sh examples/configs/diamond.json
```

Скрипты запуска поддерживают переменную `PYTHON` с путем к интерпретатору.
Если команда `python` недоступна, используйте установленный `python3` или `py`.

## Настройка приложения

Приложению передается путь к JSON-конфигурации. Все шесть полей обязательны:

```json
{
  "package": "is-odd@3.0.1",
  "repository": "https://registry.npmjs.org",
  "test_mode": false,
  "output": "../../output/is-odd.svg",
  "ascii_tree": true,
  "filter_substring": ""
}
```

Это содержимое готового файла `examples/configs/is-odd.json`.
**Относительные пути отсчитываются от папки JSON-файла.**

| Параметр | Тип | Назначение |
| --- | --- | --- |
| `package` | Строка | npm-пакет, `name@version` или тестовое имя `A` |
| `repository` | Строка | URL npm-реестра либо путь к тестовому JSON |
| `test_mode` | Логическое значение | `true` — локальный граф; `false` — npm |
| `output` | Строка | Путь к SVG; D2 сохраняется рядом с тем же именем |
| `ascii_tree` | Логическое значение | Выводить ASCII-дерево на этапе 5 |
| `filter_substring` | Строка | Исключать имена с этой подстрокой; `""` отключает фильтр |

`repository` должен указывать на npm-реестр с JSON API, а не на GitHub-репозиторий
исходного кода. Фильтр чувствителен к регистру. Исключение корневого пакета
считается ошибкой конфигурации.

Поддерживаются точные версии, dist-теги (`latest`), диапазоны `^`, `~`, `*`, `x`,
сравнения, AND-группы, `||`, диапазоны с дефисом и явно указанные prerelease-версии.
Также поддерживаются npm-алиасы. Для диапазона выбирается максимальная
подходящая опубликованная версия.

## Этапы работы

Формат команды:

```console
python src/main.py <config.json> [--stage N]
```

Если `--stage` не указан, выполняется этап **5**.

| Этап | Результат | Пример конфигурации |
| --- | --- | --- |
| 1 | Все параметры в формате `ключ=значение` | `diamond.json` |
| 2 | Прямые зависимости выбранной версии | `is-odd.json` |
| 3 | Полный список смежности и обнаруженные циклы | `cycle.json` |
| 4 | Порядок готовности пакетов: зависимости раньше потребителей | `diamond.json` |
| 5 | D2, SVG и необязательное ASCII-дерево | `string-width.json` |

Все приведенные конфигурации находятся в `examples/configs/`.

## Примеры использования

### Анализ реального пакета

```console
python src/main.py examples/configs/is-odd.json --stage 2
```

Ожидаемые прямые зависимости:

```text
is-odd@3.0.1
is-number: ^6.0.0
```

Три примера визуализации реальных npm-пакетов:

```console
python src/main.py examples/configs/is-odd.json
python src/main.py examples/configs/is-even.json
python src/main.py examples/configs/string-width.json
```

### Порядок загрузки

```console
python src/main.py examples/configs/diamond.json --stage 4
```

Результат:

```text
Load order: D -> B -> C -> A
```

### Циклические зависимости

```console
python src/main.py examples/configs/cycle.json --stage 3
python src/main.py examples/configs/cycle.json --stage 4
```

Этап 3 сохраняет ребра и сообщает о цикле `A -> B -> C -> A`.
Этап 4 завершается с ошибкой: корректный порядок для цикла невозможен.

### Фильтрация и другие тестовые случаи

```console
python src/main.py examples/configs/filtered.json --stage 3
python src/main.py examples/configs/chain.json --stage 4
python src/main.py examples/configs/isolated.json --stage 3
```

В `filtered.json` исключается B: от исходного ромба остается цепочка `A -> C -> D`.
Для цепочки порядок готовности — `C -> B -> A`, для изолированного пакета — `A`.

### Генерация всех примеров

```console
python -m scripts.demo
```

Команда сохраняет D2, SVG и текстовый вывод для пяти тестовых графов и трех
npm-пакетов в `output/`. Для генерации только локальных примеров:

```console
python -m scripts.demo --offline
```

Обе команды требуют D2. Результаты генерации исключены из Git через `.gitignore`.

## Алгоритм

1. Прочитать и проверить конфигурацию.
2. Выбрать источник: npm-реестр или локальный тестовый JSON.
3. Получить корневой пакет и разрешить его версию.
4. Рекурсивным DFS исследовать зависимости в алфавитном порядке.
5. Выполнить операцию выбранного этапа: вывести граф, порядок или визуализацию.

Узел npm идентифицируется парой **имя и версия**. Уже посещенные узлы повторно
не исследуются, но все ребра к ним сохраняются. Возврат к узлу активного стека
рекурсии фиксирует цикл, включая самозависимость.

Фильтр исключает пакет и обход через него. Его потомки остаются в графе,
если доступны по другой разрешенной ветви. Имя проверяется до запроса
метаданных; для npm-алиаса дополнительно проверяется настоящее имя пакета.
Метаданные кэшируются в памяти на время одного запуска.

Порядок готовности строится DFS postorder: узел добавляется после его зависимостей.
Это зависимостный порядок, а не хронология сетевых запросов npm.

Тестовый репозиторий задается списком смежности в JSON:

```json
{
  "A": ["B", "C"],
  "B": ["D"],
  "C": ["D"],
  "D": []
}
```

Имена состоят из больших латинских букв. Все узлы объявляются явно, включая листья.
Отсутствующие узлы, повторные ребра и неправильные списки отклоняются.

## Тестирование

Запуск тестов стандартным модулем `unittest`:

```console
python -m unittest discover -s tests -v
```

Проверяются конфигурация, ошибки реестра, выбор версий, фильтрация, циклы,
общие зависимости, порядок готовности, D2, ASCII-дерево и ошибки рендеринга.
Тесты используют подмену сетевых запросов и рендерера: интернет и D2 не нужны.
При подготовке работы прошли **23 теста**.

Проверка оформления кода:

```console
python -m pip install pycodestyle ruff
python -m pycodestyle src tests scripts
python -m ruff check src tests scripts
```

Эти инструменты нужны только для разработки. Код проверен на соответствие
PEP 8: строки Python не длиннее 79 символов, сложность функций не выше 10.

## Сравнение с npm

Для независимого сравнения установите Node.js/npm и выполните:

```console
python -m scripts.compare_npm
```

Скрипт отдельно запускает npm с отключенными lifecycle-скриптами, optional-
и автоматической установкой peer-зависимостей. Результаты записываются
в `output/comparison.json`, журналы — в `tmp/npm-comparison/`.
Само приложение npm не вызывает.

| Пакет | Узлы с корнем | Ребра | Сравнение с `npm ls --all` |
| --- | ---: | ---: | --- |
| `is-odd@3.0.1` | 2 | 1 | Все узлы и ребра совпали |
| `is-even@1.0.0` | 5 | 4 | Все узлы и ребра совпали |
| `string-width@4.2.3` | 5 | 4 | Все узлы и ребра совпали |

npm сначала запрашивает манифест родителя, чтобы узнать зависимости, и может
выполнять загрузки параллельно. Поэтому журнал сетевых запросов отличается
от порядка DFS postorder. Для независимых ветвей допустимы разные порядки.
Подробности и результаты проверки приведены в [отчете](docs/REPORT.md).

## Ограничения и ошибки

Анализируется поле `dependencies`. Модель установки npm целиком не воспроизводится:
`devDependencies`, `peerDependencies`, `optionalDependencies`, lock-файлы,
hoisting, overrides и платформенные ограничения не учитываются.
Git-, URL-, workspace- и file-зависимости не поддерживаются.

| Ситуация | Поведение |
| --- | --- |
| Некорректный JSON, параметры, URL или путь | Сообщение `Error: ...`, код возврата 1 |
| Ошибка сети или недоступный пакет | Сообщение об ошибке, код возврата 1 |
| Цикл на этапе 4 | Отказ от построения порядка с указанием цикла |
| D2 не найден | Исходник `.d2` сохранен, экспорт SVG завершается ошибкой |
| Неверные аргументы командной строки | Справка об ошибке, код возврата 2 |
| Успешное выполнение | Код возврата 0 |

Сетевой тайм-аут — 30 секунд на запрос, тайм-аут D2 — 60 секунд.
Глубина обхода ограничена допустимой глубиной рекурсии Python.
