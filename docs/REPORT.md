# Проверка варианта 26

Дата выполнения: 19.11.2026. Python 3.12.14, npm 11.19.0.
Сбор данных в приложении выполнен собственным кодом через urllib и JSON.
npm используется только отдельным скриптом сравнения.

## Этап 1: конфигурация

`python src/main.py examples/configs/diamond.json --stage 1` выводит все
шесть параметров. `tests/test_config.py` проверяет ошибки каждого параметра:
имя пакета, путь/URL, оба логических флага, путь SVG и подстроку фильтра.
Также проверяются неверный JSON, отсутствующие и неизвестные ключи.

## Этапы 2 и 3: сбор данных и DFS

Прямые зависимости `is-odd@3.0.1`: `is-number: ^6.0.0`.
Выбранная версия зависимости: `is-number@6.0.0`.

| Тестовый случай | Результат |
| --- | --- |
| Ромб | A → B, A → C, B → D, C → D; D обходится один раз |
| Цепочка | A → B → C |
| Цикл | A → B → C → A сохранен и обнаружен; C → D сохранено |
| Самозависимость | A → A сохранена и обнаружена |
| Фильтр B в ромбе | A → C → D |
| Фильтр B в цепочке | Только A |
| Изолированный узел | Только A |
| Две версии одного имени | Отдельные узлы name@version |

## Этап 4: порядок загрузки

Ромб: `D → B → C → A`. Цепочка: `C → B → A`.
Изолированный пакет: `A`. Ромб с фильтром B: `D → C → A`.
При цикле этап завершается с кодом 1 и сообщением с найденным циклом.

Фактическое сравнение выполнено командой `python -m scripts.compare_npm`.
Скрипт сравнил узлы и ориентированные ребра с `npm ls --all --json`:

| Пакет | Узлы с корнем | Ребра | Совпадение с npm |
| --- | ---: | ---: | --- |
| is-odd@3.0.1 | 2 | 1 | Все узлы и ребра |
| is-even@1.0.0 | 5 | 4 | Все узлы и ребра |
| string-width@4.2.3 | 5 | 4 | Все узлы и ребра |

Порядок готовности для is-even:

```text
is-buffer@1.1.6
kind-of@3.2.2
is-number@3.0.0
is-odd@0.1.2
is-even@1.0.0
```

Журнал реального npm `silly fetch manifest` для того же запуска:

```text
is-even@1.0.0
is-odd@^0.1.2
is-number@^3.0.0
kind-of@^3.0.2
is-buffer@^1.1.5
```

Это разные операции: рекурсивный DFS postorder определяет, когда готовы
зависимости пакета; npm запрашивает манифест родителя до обнаружения
его зависимостей. Журнал запросов не является порядком выполнения кода.
Для независимых ветвей существует несколько корректных порядков.

Подробные результаты: `output/comparison.json`; исходные журналы:
`tmp/npm-comparison/<имя>/install.log`, `npm-ls.json`, `npm-ls.txt`.
Точные версии корней закреплены в конфигурациях; версии транзитивных
зависимостей при повторе могут измениться в пределах диапазонов.

## Этап 5: визуализация

Официальный D2 0.9.0 преобразовал исходники D2 в SVG с layout `dagre`.
Сформированы восемь примеров в `output/`: пять тестовых графов и три
реальных пакета. SVG для ромба, цикла и всех трех npm-пакетов открыты
в браузере и визуально проверены: подписи читаются, стрелки соответствуют
ребрам, общие зависимости представлены одним узлом, циклы сохранены.

Примеры для трех различных пакетов:

- `output/is-odd.d2`, `output/is-odd.svg`, `output/is-odd.txt`.
- `output/is-even.d2`, `output/is-even.svg`, `output/is-even.txt`.
- `output/string-width.d2`, `output/string-width.svg`,
  `output/string-width.txt`.

ASCII-вывод приложения и `npm ls --all --unicode=false` совпадают по
пакетам, версиям и зависимостям для всех трех примеров. В выводе npm есть
дополнительный корень временного проекта `variant26-comparison`, который
не относится к анализируемому пакету и исключен из сравнения.

D2 объединяет одинаковые `имя@версия` в один узел, тогда как дерево
может показывать общую зависимость в нескольких ветвях. В нашем ASCII-выводе
повторное поддерево обозначается `[shared]`; обратное ребро цикла — `[cycle]`.
Эти различия представления не меняют граф зависимостей.

В общем случае расхождения с npm возможны из-за peer/optional-зависимостей,
lock-файла, overrides, выбора совместимых версий и правил установки.
Наш инструмент строит граф поля `dependencies`, не выполняя установку.

## Проверка качества

```console
python -m unittest discover -s tests -v
python -m pycodestyle src tests scripts
python -m ruff check src tests scripts
```

Для последних двух команд нужны только инструменты разработки:
`python -m pip install pycodestyle ruff`. Приложение от них не зависит.

Результат: 23 теста пройдены; `pycodestyle` и `ruff` без замечаний.
Дополнительно проверено: функции не длиннее 40 строк, исходники Python
не содержат строк длиннее 79 символов, сложность функций не выше 10.
Дополнительное сравнение с semver из установленного npm: 368 сочетаний
версий и диапазонов совпали, включая prerelease у частичных верхних границ.
